# Security and Compliance

> **Scope update (2026-10-30):** The initial no-upload/read-only dashboard rules below describe the existing sports dashboard, not permission to build an unsafe general workspace. Any future CSV upload UI must implement size/decompression limits, defensive parsing, project/session isolation, explicit retention/deletion behaviour, safe exports, and no external sharing of private uploads without informed consent. The product-level requirements are in [WORKSPACE_PRODUCT_DIRECTION.md](WORKSPACE_PRODUCT_DIRECTION.md).

v1 has no user accounts, no payments and no personal data beyond public athlete names, so the attack surface is small. The rules below keep it that way, and define what must change if authentication is ever added.

## 1. Secrets
- Real values only in `.env` (gitignored). `.env.example` lists variable names with dummy values.
- GitHub Actions secrets for CI and scheduled runs.
- Add a pre-commit secret scan (for example `gitleaks`) and run it in CI.
- If a secret is ever committed, rotate it immediately. Deleting the commit is not enough.
- Logs must never contain secrets or full request headers.

## 2. Outbound access (scraping ethics and legality)
- Check and record `robots.txt` and terms of use per source (Phase 0).
- Honest `User-Agent` with contact information.
- Rate limit, cache, back off, stop on 403 or 429.
- Do not bypass logins, paywalls, CAPTCHAs or other access controls.
- Store facts (results) with source links. Do not republish full copyrighted pages, images or articles. Quoting short factual values is fine.
- If a source forbids automation, use manual import. Do not work around it.

## 3. Input handling
- All external data is untrusted. Parse defensively, validate with pydantic, never use `eval`, never execute fetched content.
- SQL is always parametrised (SQLAlchemy). No string-built queries.
- File paths for raw storage are generated by code from safe components, never from remote strings.
- Manual CSV import validates headers, types and sizes.
- Playwright (if used) runs without access to local credentials and only on allow-listed domains.

## 4. Dependencies
- Pin versions (lock file). Run `pip-audit` in CI. Update on a schedule.
- New dependencies need justification in the PR (see `AGENTS.md`).

## 5. Dashboard
- Read-only. No write paths, no file upload, no SQL input box.
- If hosted publicly, expose only aggregated and sourced facts. The database file with operational tables (runs, quarantine) stays private.
- No secrets in front-end code or in the repository.

## 6. LLM layer (optional)
- API key in environment variables only.
- Send only computed aggregate tables. No raw scraped text as instructions (prompt injection risk: scraped pages may contain hostile text).
- Output is labelled as generated. Numbers are verified against the computed tables before display; mismatch means discard the text.

## 7. If authentication is added later (not v1)
Treat as a design change with a decision record, and then:
- Passwords hashed with Argon2id (bcrypt acceptable). Never stored or logged in plain text.
- Separate authentication (who you are) from authorization (what you may do); roles such as Admin, Analyst, Viewer, enforced on the server for every request.
- Secure session or token handling: expiry, HTTP-only and secure cookies, CSRF protection where cookies are used, refresh and revocation strategy.
- Rate limiting and lockout on login, HTTPS only, audit log of sensitive actions.
- Security tests: unauthenticated access, wrong role, expired token, injection attempts.

## 8. Backups and integrity
- Raw store plus migrations plus reference CSVs are enough to rebuild the database. Keep copies of `data/raw/` and `data/reference/` outside the working machine (for example a private repository or cloud drive).
- Test a restore once per phase.
- Database dumps are never stored or uploaded in the clear. `sie backup --require-encryption` encrypts with `age` to a public recipient (`BACKUP_AGE_RECIPIENT`); the private identity lives only in the `BACKUP_AGE_IDENTITY` secret and an offline copy, never in the repository, logs or artifacts. The repository is public, so artifacts are world-readable by signed-in users: only `*.dump.age` and manifests may be uploaded (enforced by a guard step). Restore tests run in a scratch database and are refused against `DATABASE_URL`. Runbook: `DEPLOYMENT.md` section 3a, ADR-034.

## 9. Evidence ledger (ADR-042)
- Uploads are per-project copies; reads go through a scoped API and composite foreign keys, and a cross-project request is indistinguishable from a missing id.
- Uploads are limited in size and decompressed size, hashed, and the filename is sanitised before use. Stored bytes are never executed or rendered.
- Purge and prune are owner-only (database privilege check), dry-run by default and confirmed explicitly. They do not erase backups or provider history; the Neon window is unverified until the owner records it. See `EVIDENCE_RETENTION.md`.
- Full web copies need a recorded permission; the default keeps an excerpt only.

## 10. Web fetching (ADR-044)
- Only https; a URL with credentials is refused. The host name must resolve to public addresses only and the connected address is checked again (loopback, private, link-local, multicast and metadata addresses are refused).
- robots.txt is read per host and obeyed; if it cannot be read the fetch stops. At least 2 seconds between requests to a host; a 403, 429 or 5xx stops the host for the run.
- One redirect at most, to the same host only. Content type and size are limited and compressed responses are refused. Nothing fetched is executed or rendered.
- The real network function is not run in CI; the owner does the first live test. No workflow fetches anything.


## 10. ResearchFlow workspace and source-policy requirements (2026-10-29)
The product-level rules are in `WORKSPACE_PRODUCT_DIRECTION.md`. Apply them to every source adapter and future UI:

- Separate user approval from technical access, source terms, licence/allowed use, privacy, and retention. A user approving a URL never overrides source restrictions.
- In selected-source mode, do not silently switch to another source. If the selected source has no suitable data, tell the user and ask whether global discovery may be used, unless the user has explicitly enabled global fallback in settings.
- In global-discovery mode or with previously enabled fallback, try other eligible sources without repeated prompts, but apply the same access, licence, privacy and retention checks to every source.
- Do not bypass login, paywall, CAPTCHA, 403/429 restrictions or rate limits. Stop that route and offer an eligible alternative source or manual upload. Only transient errors may be retried under bounded backoff and source limits.
- If analysis is allowed but redistribution is restricted, do not include restricted raw data in public exports. Check derived-output permissions too. If licence/use is unclear, pause broader retention or redistribution until clarified.
- Private uploads must not be sent to public websites or unrelated providers/models without explicit disclosure and consent.
- Never claim universal fetch success. Track discovery, fetch, parse/validation and end-to-end completion separately; show clear failure reasons.

## 11. Three independent source-permission checks and fallbacks
Before a source is fetched, reused or exported, record separately:
1. **User source choice:** the user selected/approved the source or enabled global discovery. Do not silently change sources in selected-source mode.
2. **Automated access:** documented API rules, source terms, robots guidance and access controls permit the intended request. User approval does not override these restrictions.
3. **Intended use:** the licence/policy permits the specific analysis, retention, transformation, export, sharing or redistribution. Public availability alone is not a reuse licence.

If user source approval is missing, explain what was checked and ask whether global discovery is allowed; use other sources automatically only if the explicit global-fallback preference is enabled. If automated access is blocked, stop that route and offer an official permitted API/download, documented alternate format/endpoint, correctly paginated access, bounded retry for transient failures, another eligible source when source mode allows it, or manual upload. Never bypass login, paywall, CAPTCHA, robots/terms restrictions, 403/429 blocks or rate limits. If raw redistribution is not allowed, exclude raw rows/files from exports; only offer attributed aggregates/charts if both the licence and the derived-output context permit sharing. If licence terms are unclear, pause broader retention/redistribution and request clarification or use a clearly permitted alternative. If no permitted source supports a reliable answer, report the gap rather than fabricate or silently substitute data.
